# 技术博客写作规范

归纳自 `content/post` 下已发表的技术文章（video-codecs、gpu-memory、compute-chips、jepa、deepseek-v4），用于新文章撰写与旧文修订时的自检。

## 一、结构

- 正文第一个 H2 固定为「引子」（偏说明性的长文可用「引言」），前面不加大纲、摘要、目录。
- 引子第一段只写一个具体触发点：一个工程痛点、一次报错、一条新闻或一句自嘲。禁止「随着……的发展」式宏观背景。
- 引子第二段写路线图，句式固定为「先……再……然后……最后……」，并说明本文不覆盖什么。整个引子控制在两段、约 250 字以内。
- H2 用 4–10 字的名词短语陈述句，括号里只放英文或缩写。标题不用问句。
- H2 保持 3–6 个，按「概念 → 算账 → 优化 → 调试」递进，不按知识点平铺。
- 主线之外的推导、延伸分类、长代码，一律折叠进 `{{< details "名词短语" >}}` 或 `<details><summary>`。
- 篇幅足够时用「## 结语」或「## 收尾」：写清覆盖边界、目标读者、局限与致谢，禁止复述正文。短篇可省略，停在一个可操作结论上。

## 二、段落

- 单段 90–140 字、2–4 句，一段只讲一个点，段首句即论点。
- 超过 200 字的段落只允许出现在综合权衡或单题深入处，且首句先给结论。
- 段间用一句判断句直接推进，不设过渡小节，段首不用「首先/其次/最后」串场。
- 路线图句只出现在引子，正文不再重复。

## 三、术语

- 首现写成「中文（English, ABBR）」，之后统一用缩写。
- 术语出现前，先用一句已知经验、已有机制或日常类比铺垫，再给定义。常用句式：「在介绍 X 之前，先用 Y 做一个铺垫」「可以把它理解成……」。
- 定义后紧跟一句可量化的「所以它影响什么」，例如「相差约 50 倍」。
- 公式后逐符号列 bullet 解释，并注明假设条件。
- 关键约束和易错点用加粗或「注意：」单句点出。
- 禁止在没有铺垫的情况下直接抛出新术语。

## 四、数据与算账

- 每个量级结论都配一次可复现换算，写进 ```` ```text ```` 块，使用 `≈` 和单位。
- 换算前先声明基准（分辨率、帧率、模型规模、并发数），全文统一。
- 算完必须落一句人话结论，例如「超过权重的四倍」「单卡必然放不下」。
- 严格区分理论值与实测值：估算加「约」，并说明「只适合判断量级」。
- 命令和脚本用可运行的 bash/python 块，关键行加中文行尾注释。
- 对比实验给成对命令或前后数字，保证读者能自己复现。

## 五、表格与列表

- 表格只用于三类场景：分类盘点、横向对比、参数速查。其余场景改用列表。
- 表格前加一句引导句，表格后加一句「怎么读这张表 / 怎么用这张表」。
- 对比表列序固定为「对象 | 维度…… | 说明/场景/原因」，末列回答「什么时候用、代价是什么」。
- 需要长注释或来源说明的表格包进 `<figure>` + `<figcaption>`；自解释的表用纯 Markdown 表格。
- 并列项用「- **短语**：解释」的加粗领起；决策流用有序列表，写成「是不是 X？是，就 Y」。
- 单个列表项不超过两句，超出的内容下沉为子小节或折叠块。

## 六、配图与引用

- 配图手写 HTML，不用 Hugo shortcode：

```html
<figure>
  <img src="xxx.svg" alt="中文短语" style="width:78%;" />
  <figcaption>怎么看这张图，一句话</figcaption>
</figure>
```

- 宽度按需取 60%/78%/80%/92%，需要居中时加 `display:block;margin:0 auto;`。
- 图注 15–60 字，写「箭头/曲线怎么看」而不是「这是什么」。AI 生成的图注明来源。
- 需要被正文跳转的图或段落前加 `<a id="kebab-case"></a>`，正文用 `[描述](#id)` 回跳。
- 硬结论（标准、论文、工具行为）一律给脚注，格式为「作者/机构. 标题. URL」或「作者. 标题. arXiv:ID, 年. URL」，文末按首次出现排序。
- 官方文档与规范优先；百科只用于背景词，且用行内链接而不是脚注。
- 链接文字用中文描述，不出现裸 URL。
- 引用自家文章用 `/p/<slug>/`，可带锚点，且不重复解释已写过的内容。

## 七、frontmatter

```yaml
---
title: "GPU 显存：从原理到优化"
description: "从显存的基本概念讲起，估算训练与推理的占用，再总结降低用量的思路"
slug: gpu-memory
date: 2026-03-12 10:00:00+0800
draft: false
image: ""
categories:
  - 技术杂谈
tags:
  - 显存
  - 性能优化
authors:
  - "Yukun Zhou"
type: post
---
```

- `title` 用双引号中文，8–19 字，可用中文冒号分「主题：副题」，不加句号、问号、感叹号；英文与中文之间留空格。
- `description` 20–50 字，是引子路线图的压缩版。
- `slug` 用 kebab-case，与目录名一致；组织形态固定为 `content/post/<栏目>/<slug>/index.md`，图片与 `index.md` 同目录。
- `categories` 1–2 个中文宏观分类，`tags` 1–2 个专有名词，不用泛词。
- 有公式时加 `math: true`。

## 八、语言风格

- 不用「我们」；「你」极少量使用，只出现在玩笑句里。主语以无主语句和第三人称群体为主（「跑大模型的人」「工程上」）。
- 第一人称只出现在主观段落（「个人比较常用的是……」）。
- 每篇 2–4 个比喻，且必须服务机制解释，不用于修辞。
- 每个优化方法都要补一句「代价」。
- 语气词克制，只出现「就行」「不用管」「错漏难免」这类，不用「啦/哦/呢」。
- 标点用全角中文引号「“”」和破折号「——」；数字与英文前后留空格；`code` 用于标识符和命令，加粗用于概念与关键约束。
- 固定小装置：绿色高亮 span 给定义，橙色 span 给提醒与致歉。

## 九、发布前检查清单

- [ ] 第一个 H2 是「引子」，引子只有两段且含路线图
- [ ] 小节标题都是 4–10 字名词短语，没有问句
- [ ] 新术语都有「中文（English, ABBR）」和一句铺垫
- [ ] 每个量级结论都有可复现换算，且落在人话结论上
- [ ] 每张表都有引导句和「怎么用」
- [ ] 每张图都是 `<figure>` + 单句 `<figcaption>`
- [ ] 硬结论都有脚注，链接文字是中文
- [ ] 每个优化方法都写了代价
- [ ] frontmatter 字段齐全，slug 与目录名一致
- [ ] 全文没有「我们」，没有冗余过渡句
